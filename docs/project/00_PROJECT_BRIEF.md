## 3. 서비스와 워크로드 분해 (확정)
**서비스**: 한국어 사용자를 위한 영어 일상회화 학습 서비스. 학습자는 회화 시나리오를 골라 챗봇과 대화하고, 틀린 표현을 오답노트에 저장해 복습한다.

| ID | 워크로드 | 성격(RFP 가/나/다) | 트래픽 | 변경 주기 | 상태 | 배치 |
|---|---|---|---|---|---|---|
| A | **content** — 학습 콘텐츠(회화 시나리오·주제 마스터) 관리 API | 가: 상태 유지·변경 드묾 | 낮고 일정 | 분기 단위 | RDS에 정합성 데이터 보유 | **VM (EC2 ASG)** |
| B | **chat** — 회화 챗봇 API (FastAPI + LLM) | 나: 잦은 배포·수평 확장 | 사용자 수에 비례·변동 | 주·일 단위(프롬프트 수정) | 무상태(대화 이력은 요청에 포함) | **Container (EKS)** |
| C | **note** — 오답노트/복습 문장 저장 | 다: 간헐·이벤트성 | 학습 종료 시점에만 | 독립 소규모 배포 | 무상태 함수 + DynamoDB | **Serverless (API GW + Lambda)** |

- DB(RDS, DynamoDB)는 워크로드가 아니라 **공유 자원(C5)**.
- WEB/WAS/DB 계층 분할이 아님 → 서로 다른 업무 기능.

### ADR-1 (배치 근거) 요지
- A→VM: 데이터 정합성 최우선, 변경 드묾, 트래픽 예측 가능 → 상시 기동 + 인스턴스 단위 복구로 충분. 운영자(관리자) 소수.
- B→EKS: 프롬프트·로직 잦은 변경 → 롤링 배포, 사용자 증가 시 Pod 수평 확장, Pod 단위 자가 복구.
- C→Lambda: 평소 호출 거의 없음, 학습 종료 시 몰림 → 상시 서버 낭비, 호출당 과금.

### ADR-2 (버린 대안) 후보
1. 챗봇을 Lambda로: LLM 응답 지연(수 초)·콜드스타트·잦은 배포 시 함수 버전 관리 부담 → 기각. 포기한 것: 유휴 비용 0.
2. 콘텐츠 API를 컨테이너로: 가능하지만 변경 드물어 오케스트레이터 이득 적음 → VM. 포기한 것: 배포 속도·밀도.
3. EKS 대신 ECS Fargate: 운영 부담↓, 하지만 RFP 권장이 K8s + 실무 표준 학습 → EKS. 포기한 것: 단순성·비용.
4. NAT GW 2개(AZ별) 대신 1개: 비용 절감, 포기한 것: NAT AZ 장애 내성 (Day 단위 PoC라 수용).
5. 벡터DB/RAG: 기능 채점 안 함 → 제외.

## 4. 설계 제약 C1~C10 (위반 시 해당 항목 0점)
| No | 제약 | 우리 설계의 충족 방법 |
|---|---|---|
| C1 | 단일 VPC·다중 AZ | VPC 1개, 2a/2c. EC2 ASG·EKS 노드·**Lambda(VPC 연결)**·RDS Multi-AZ 모두 2AZ |
| C2 | 세 컴퓨팅 유형 사용 | A=EC2, B=EKS, C=Lambda |
| C3 | 유형별 외부 엔드포인트 ≥1 (총 3) | 외부 ALB(A), Ingress ALB(B), API GW URL(C) |
| C4 | 이종 워크로드 간 데이터 연동 ≥1 | **B(Pod) → 내부 ALB → A**(시나리오 조회). (선택) B → C 오답노트 저장 |
| C5 | 영속 저장소 2종 | RDS MySQL(관계형) + DynamoDB(NoSQL) |
| C6 | 데이터 계층 비노출 | RDS: private data 서브넷, publicly_accessible=false, SG는 A의 SG만. DynamoDB: IAM 최소권한 + Gateway Endpoint (+권장: 테이블 정책 aws:SourceVpce 제한) |
| C7 | 크리덴셜 외부화 | RDS 관리형 시크릿(Secrets Manager), IAM Role(Instance Profile/IRSA/Lambda Role). Access Key 미발급 |
| C8 | 자원 식별자 기반 접근 제어 | SG 소스는 **SG ID만** (외부 ALB 80/443만 0.0.0.0/0 예외), IAM 정책 리소스 ARN 한정 |
| C9 | 자동 복구 실증 | EC2 terminate → ASG 재생성 / Pod delete → ReplicaSet 복원 (전·후 캡처) |
| C10 | 환경 및 완주 | ap-northeast-2·지정 계정만, 마감 시 E2E 동작 |

## 5. 요구사항 체크 (필수 1~8, 가점 9·Opt)
1. 서비스 정의(10줄 이내) + 워크로드 3개 특성표 + 배치·기각 대안 → 위 3장
2. VM: 사람 접속 없이 자동 기동(User Data), 호스트명+데이터 1건 응답, **삭제 후 재생성해도 동일 상태**
3. Container: 이미지 직접 빌드→ECR→EKS, 외부 엔드포인트, **replica ≥2 + probe**, 컨테이너 이름 응답, Pod 삭제 시 자동 복원
4. Serverless: 상시 서버 없이 요청→함수→저장소 경로, 입력 1건 저장 후 결과 반환
5. 저장소 2종 근거, 이종 연동 1건, 자원 식별자 기반 접근제어, 크리덴셜 주입 방식 기술
6. **3×4 운영 매트릭스 12칸** (배포/재배포/강제종료 복구/용량 2배) 방법·소요시간 + 비교 5줄
7. VPC CIDR·서브넷 설계안(크기 근거), Naming/Tag 체계 적용
8. **AI 협업 4종 기록** → `docs/ai-log.md`
9. (가점) 최소권한·MFA·SSM 접근 / CloudWatch 알람→SNS 수신 증적 / 월 비용 산정·절감안
Opt. (가점) IaC(Terraform), HPA 부하 자동확장 실증
