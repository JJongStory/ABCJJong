## 2. Bedrock (사용량 비례)

| 가정 | 값 |
|---|---|
| 사용자 × 하루 대화 턴 × 일수 | 50명 × 20턴 × 30일 = **월 30,000회 호출** |
| 호출 1회 입력 | 약 650토큰 (시스템 프롬프트 + 대화 이력 6개 + 사용자 문장) |
| 호출 1회 출력 | 약 220토큰 (출력 상한 `maxTokens` 600) |
| 단가 (Claude Haiku 4.5, Global 추론 프로파일) | 입력 $1 / 출력 $5 (백만 토큰당) |
| 호출 1회 | 650 × $1/1M + 220 × $5/1M ≈ **$0.00175** |
| 사용자 1명 월 | 600회 × $0.00175 ≈ **$1.05** |
| **50명 월** | **약 $53** (출력이 매번 상한 600까지 가는 최악의 경우 약 $110) |

**합계: 약 $381/월** (최악 약 $438/월)

## 3. 사용자 증가 시나리오

| 사용자 | Bedrock/월 | 필요한 증설 |
|---|---|---|
| 50 | $53 | 현재 구성 그대로 (동시 사용 약 5명) |
| 200 | $210 | HPA 범위(최대 6) 안에서 Pod 확장. Bedrock 호출 한도 확인 |
| 500 | $525 | 노드 2→4대, NAT AZ별 이중화, RDS 사양 상향, VM 최소 2대 (인프라 약 +$167). 노드 오토스케일러, 호출 한도 증설 |
| 1,000+ | $1,050+ | 처리량 예약 요금제 검토, 사용자별 하루 호출 상한 |

Bedrock 비중: 50명 약 14% → 500명 약 50%. 사용자가 늘수록 비용의 중심이 고정 인프라에서 LLM 사용량으로 이동하므로, 인프라 증설보다 **LLM 사용량 통제**를 먼저 설계했다.
