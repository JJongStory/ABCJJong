# ADR — 아키텍처 의사결정 기록 (발표 4·5장 원천)

## ADR-1. 워크로드별 실행 환경 배치

**맥락**: 서비스는 한국어 사용자를 위한 영어 일상회화 학습 서비스이다. 하나의 서비스를 업무 기능(워크로드) 3개로 분해해 VM / Container / Serverless에 각각 배치하고, 같은 운영 작업(배포·재배포·복구·증설)을 반복해 차이를 숫자로 기록하는 것이 1순위 목적이다. 평가 대상은 실행 환경이며 앱 기능이 아니다.

| 워크로드 | 성격 | 트래픽 | 변경 주기 | 상태 | 결정 |
|---|---|---|---|---|---|
| A. content (학습 콘텐츠 관리 API) | 상태 유지·변경 드묾 | 낮고 일정 | 분기 단위 | RDS에 정합성 데이터 | **VM (EC2 ASG)** |
| B. chat (회화 챗봇 API) | 잦은 배포·수평 확장 | 사용자 수에 비례, 변동 | 주·일 단위(프롬프트 수정) | 무상태(이력은 요청에 포함) | **Container (EKS)** |
| C. note (오답노트 저장) | 간헐·이벤트성 | 학습 종료 시점에만 | 독립 소규모 배포 | 무상태 함수 + DynamoDB | **Serverless (API GW + Lambda)** |

### 결정 A → VM
- **이유**: 데이터 정합성이 최우선이고 변경이 드물며 트래픽이 예측 가능하다. 상시 기동 + 인스턴스 단위 복구(ASG)로 충분하고 운영자도 소수다.
- **결과**: User Data로 사람 접속 없이 자동 기동, 삭제 후 재생성해도 동일 상태. 단일 인스턴스라 복구 중 짧은 다운타임을 **수용**하고 매트릭스에 기록한다.

### 결정 B → Container (EKS)
- **이유**: 프롬프트·로직이 자주 바뀌어 롤링 배포가 필요하고, 사용자 증가 시 Pod 수평 확장, Pod 단위 자가 복구가 맞는다. 무상태라 세션 공유가 필요 없다.
- **결과**: replica ≥2 + probe, HPA(가점). 클러스터 생성에 15~20분이 들고 컨트롤플레인 상시 비용이 발생하는 비용을 **수용**한다.

### 결정 C → Serverless
- **이유**: 평소 호출이 거의 없고 학습 종료 시점에 몰린다 → 상시 서버는 낭비, 호출당 과금이 유리하다.
- **결과**: 요청 → 함수 → DynamoDB 경로, 콜드스타트와 VPC 연결 ENI를 **수용**한다. 증설은 reserved concurrency 조정으로 즉시.

### 공통 결정
- DB(RDS, DynamoDB)는 워크로드가 아니라 **공유 자원**이다. WEB/WAS/DB 계층 분할이 아니라 서로 다른 업무 기능으로 나눈다.
- 이종 연동(C4): B(Pod) → 내부 ALB → A. 내부 ALB의 SG 소스는 EKS cluster SG ID(C8).

## ADR-2. 버린 대안과 트레이드오프

| # | 버린 대안 | 기각 이유 | **포기한 것(트레이드오프)** |
|---|---|---|---|
| 1 | 챗봇(B)을 Lambda로 | LLM 응답 지연(수 초)·콜드스타트, 잦은 배포 시 함수 버전 관리 부담 | 유휴 비용 0 |
| 2 | 콘텐츠 API(A)를 컨테이너로 | 가능하지만 변경이 드물어 오케스트레이터 이득이 적음 → VM | 배포 속도·밀도 |
| 3 | EKS 대신 ECS Fargate | 운영 부담은 낮지만 RFP 권장이 K8s이고 실무 표준 학습 가치가 있음 → EKS | 단순성·비용 |
| 4 | NAT GW 2개(AZ별) 대신 1개 | 비용 절감 | NAT AZ 장애 내성 (Day 단위 PoC라 수용) |
| 5 | 벡터DB/RAG | 기능은 채점 대상이 아님 → 제외 | 챗봇 응답 품질 |

### 요약
- 모든 선택은 "RFP 목적(세 실행 환경의 운영 차이 측정)에 맞는가"와 "1~3일 PoC 범위에서 설명·재현 가능한가"로 판단했다.
- 포기한 항목은 모두 비용 또는 가용성 내성이며, 발표 15장 회고에서 개선안(절감안은 `docs/cost.md`)으로 다시 다룬다.
